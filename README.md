# Garmin Running Dashboard

Дашборд тренировок и показателей здоровья. И локально, и на Vercel backend
читает данные напрямую через Garmin Personal API. Запись в Garmin Connect
приложение не выполняет. Сводки хранятся в SQLite или PostgreSQL по аккаунтам.

Публичное демо использует вымышленные данные. Garmin Personal API key и
необязательный ключ GigaChat добавляются после входа, в настройках аккаунта.
Для тренера в GigaChat отправляется сводка выбранного периода по запросу.

Структура фронтенда описана в [ARCHITECTURE.md](frontend/ARCHITECTURE.md).

## Как работает план недели

- Настройки бегуна и доступные дни хранятся в аккаунте. Backend рассчитывает
  черновик по свежей истории Garmin, привычному объёму, этапу подготовки и
  отмеченным разгрузочным неделям. Создание черновика не вызывает GigaChat.
- Подтверждённый план хранится отдельно от черновика. Сверка с Garmin сравнивает
  даты, вид занятия и беговой объём на текущую дату. Запись пробежки сама по себе
  не подтверждает темп или интервальную структуру.
- ИИ получает краткие результаты сверки, ближайшее занятие, цель и последние
  реплики. Он объясняет отклонения и предлагает корректировки. Подтверждённый
  план автоматически не меняется.

## Локальная проверка личного кабинета

Запускай команды из корня проекта. Для SQLite оставь `DATABASE_URL` пустым
в локальном `.env` либо убери эту строку. Перед первым запуском добавь ключ
шифрования в `.env` следующей командой, если переменной ещё нет.

```bash
grep -q '^SECRETS_ENCRYPTION_KEY=' .env 2>/dev/null ||
  python3.12 -c 'import secrets, base64; print("\nSECRETS_ENCRYPTION_KEY=" + base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())' >> .env
docker compose up --build
```

Если строка `SECRETS_ENCRYPTION_KEY=` уже есть, но пустая, удали пустую строку
и выполни команду генерации. Сохрани этот ключ между запусками: он нужен
для расшифровки ранее сохранённых ключей Garmin и GigaChat.

Открой http://127.0.0.1:8080. Зарегистрируйся с email и паролем от 10 символов.
В настройках сохрани Garmin Personal API key, затем нажми «Проверить».
После успешной проверки нажми «Обновить Garmin» в дашборде. Ключ GigaChat
Authorization Key можно добавить и проверить отдельно. Для GigaChat
используются серверные настройки сертификатов, модели и scope из Docker Compose.

Локальный Docker хранит базу в `backend/data/dashboard.sqlite3`. Для PostgreSQL
укажи `DATABASE_URL` на стороне backend. Историю старого общего JSON приложение
автоматически не присваивает новым аккаунтам. Для проверки изоляции выйди и
создай второй аккаунт: в нём история и настройки должны быть пустыми.

## Личные кабинеты на Vercel

1. Импортируй этот же репозиторий во второй проект Vercel с Root Directory
   `backend` и пресетом FastAPI. Подключи к нему Neon PostgreSQL.
2. В Production переменных backend проверь строку подключения.
   Если Neon добавил `GARMIN_DATABASE_URL`, `GARMIN_POSTGRES_URL` или
   `GARMIN_DATABASE_URL_UNPOOLED`, можно использовать её автоматически.
   Ручной `DATABASE_URL` имеет приоритет. Затем добавь отдельный ключ
   Fernet в `SECRETS_ENCRYPTION_KEY` и полный HTTPS адрес фронтенда
   в `APP_ORIGIN` без слеша на конце. Если GigaChat требует сертификаты,
   настрой его CA bundle в backend.
3. Разверни backend и проверь его маршрут `/api/health`. В существующий
   проект Vercel с Root Directory `frontend` добавь `BACKEND_ORIGIN`
   с HTTPS адресом backend. После этого установи `VITE_PUBLIC_DEMO=false`
   и запусти новый деплой фронтенда. Запросы браузера идут через его домен.
4. Проверь регистрацию, вход и выход. Демо доступно до входа.
   Проверь ключ Garmin и отдельно синхронизацию. На Vercel они обращаются
   к внешним сервисам, а длительность запроса синхронизации ограничена
   тайм-аутом функции. Локальная база SQLite в облако не переносится.

### Восстановление пароля

Для отправки писем настрой Resend. Подтверди домен отправителя и добавь в окружение бэкенда `RESEND_API_KEY` и `PASSWORD_RESET_FROM` (например, `noreply@your-verified-domain.com`). В `APP_ORIGIN` укажи адрес фронтенда, который получатели смогут открыть. Для локального теста в Docker подойдёт `http://127.0.0.1:8080`, если открываешь письмо на той же машине.

На Vercel эти три переменные задаются в проекте API. После выкладки открой «Войти → Забыли пароль?» и проверь письмо на тестовом аккаунте. Ссылка действует 30 минут. После смены пароля завершаются все сессии этого аккаунта.
